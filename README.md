# Астрометрия астероида (7065) Fredschaaf

## Быстрый старт

Среда проекта уже описана в `requirements.txt`. Один раз создайте её и
зарегистрируйте kernel:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m ipykernel install --prefix "$PWD/.venv" \
  --name fredschaaf-astrometry \
  --display-name "Python (Fredschaaf astrometry)"
chmod +x run_jupyter.sh
./run_jupyter.sh
```

В Jupyter откройте `reductions.ipynb` и выберите kernel **Python (Fredschaaf
astrometry)**. Это простая астрометрическая калибровка одного WCS-решённого
кадра по опорным звёздам Gaia: notebook показывает совпадения, измеряет центры
звёзд, строит линейную привязку и выводит RMS остатков в mas.

Сложный экспериментальный конвейер сохранён в `reductions_advanced.ipynb`.
Результаты пользовательских запусков сохраняйте в `outputs/`; каталог намеренно
не входит в репозиторий.

## Задача проекта

Цель проекта — построить воспроизводимый конвейер высокоточной относительной
астрометрии слабого астероида **(7065) Fredschaaf = 1992 PU2** по сериям коротких
FITS-экспозиций.

Первый практический результат должен быть не «обнаружением спутника», а надежной
таблицей положений астероида с временами, ошибками, признаками качества и одним
репрезентативным положением на центральный момент каждой серии. После этого можно
проверять, содержат ли остатки движения согласованный периодический сигнал
фотоцентра.

Проект отвечает на четыре последовательных вопроса:

1. Можно ли автоматически и надежно найти слабый движущийся объект на кадрах?
2. Какую точность дает один кадр, короткий подстек и целая серия?
3. Насколько хорошо движение внутри серии описывается прямой или полиномом низкой
   степени без привязки результата к постоянно обновляемой эфемериде?
4. Остается ли после удаления движения статистически значимый и воспроизводимый
   сигнал, совместимый с движением фотоцентра двойного астероида?

## Научная мотивация и ожидаемый сигнал

В работе Liberato et al. (2024) Fredschaaf включен в список кандидатов в двойные
астероиды по астрометрии Gaia DR3. Машинно-читаемая строка каталога CDS для объекта
7065 содержит:

- оценку периода wobble-сигнала: **94.864 ± 1.81 часа** (около 3.953 суток);
- оценку амплитуды: **8.05 ± 0.71 mas**;
- флаг лучшего поднабора `S/N > 1`: установлен;
- флаг двойного решения: не установлен.

Это априорная гипотеза, а не подтвержденный спутник. Периодический сдвиг фотоцентра
может быть вызван спутником, но вклад также могут дать неправильная форма тела,
вращение, неоднородное альбедо, фазовый угол и инструментальные систематики.

Масштаб камеры на решенных кадрах составляет примерно **0.488 arcsec/pixel**.
Следовательно, 8.05 mas соответствуют всего **0.0165 пикселя**. Измерить такой
сдвиг на одном кадре невозможно: необходимы многочисленные измерения, корректная
модель общих систематик и наблюдения на разных фазах предполагаемого периода.

Важно: имеющиеся серии сами по себе недостаточны для независимого подтверждения
периода около 95 часов. Самая длинная ночь покрывает меньше часа, а сигнал с таким
периодом внутри нее почти неотличим от постоянного слагаемого и небольшого наклона.
Текущий набор предназначен прежде всего для разработки и проверки измерительного
конвейера и оценки достижимой точности.

### Пример астрометрической калибровки

В `exam/` находятся:

- `astrometric_calibration.ipynb` — пример линейной астрометрической редукции;
- `Fredschaaf_R.fits` — WCS-решенный тестовый кадр от 2025-10-10.

Notebook уже реализует полезный baseline:

- вычисляет центральный момент экспозиции;
- получает локальную выборку Gaia DR3;
- переносит координаты звезд на эпоху наблюдения по собственным движениям;
- использует WCS для первичного отождествления;
- определяет центры звезд эллиптическим гауссовым профилем;
- строит линейную модель `x, y → ξ, η`.

В сохраненном запуске использованы 24 опорные звезды, а RMS составляет примерно
40 mas по одной координате и 97 mas по другой. Это стартовый контрольный уровень,
а не конечная точность.

Перед переносом notebook в рабочий pipeline надо исправить и дополнить следующее:

- в выводе формулы для `eta` по ошибке печатается `ax` вместо `ay`;
- суммы квадратов остатков `r_xi` и `r_eta` присвоены противоположным переменным;
- обычный МНК не использует индивидуальные ошибки и чувствителен к выбросам;
- у гауссовой модели нет ограничений параметров и маски насыщенных/плохих пикселей;
- перенос Gaia не включает параллакс и более полную модель движения наблюдателя;
- нет цветовой поправки/DCR, общей модели дисторсии и frame-by-frame диагностики;
- ошибка калибровки не переносится в ковариацию положения астероида;
- notebook работает с одним кадром и не создает машинно-читаемого результата серии.

Исходный notebook следует сохранить как учебный пример. Рабочие функции лучше
перенести в тестируемые модули и запускать пакетно из командной строки.

## Основной принцип анализа

Эфемерида нужна для первичного поиска объекта, проверки грубых ошибок и построения
диагностических O−C. Она не должна определять внутрисерийную базовую линию.

Для каждой непрерывной серии измеренные положения переводятся в общую касательную
плоскость и описываются локальной моделью времени. Для центральной эпохи `t0`:

```text
τ = t − t0
ξ(t) = ξ0 + vξ τ [+ 1/2 aξ τ²]
η(t) = η0 + vη τ [+ 1/2 aη τ²]
```

где `ξ ≈ Δα cos δ`, `η ≈ Δδ`. Основной публикуемый результат серии — `ξ0, η0`
или соответствующие `RA, Dec` на `t0`, их полная ковариация, число кадров и
показатели качества.

Линейная модель является исходной. Квадратичный член добавляется только если его
требуют длительность серии и проверка по остаткам/cross-validation. Полином высокой
степени способен поглотить искомый медленный сигнал, поэтому автоматически
увеличивать степень нельзя.

## Предлагаемый конвейер

### 1. Инвентаризация и проверка времени

Для каждого FITS создать строку таблицы `frames`:

- путь и контрольная сумма файла;
- `DATE-OBS`, `DATE-END`, `EXPTIME`, центральный UTC, JD и BJD/TDB при необходимости;
- фильтр, gain, температура, размер, тип данных;
- наличие и параметры WCS;
- медиана фона, шум, FWHM, эллиптичность, число звезд, признаки облачности;
- флаги saturation, tracking failure, edge и других дефектов.

Центральное время первоначально вычисляется как `DATE-OBS + EXPTIME/2`, но надо
сравнивать его с `(DATE-OBS + DATE-END)/2`: просмотренные значения `DATE-END` дают
интервалы немного длиннее номинальных 5 секунд. Перед высокоточным анализом нужно
выяснить смысл этих ключей, задержку затвора и точность синхронизации компьютера.

### 2. CCD-калибровка

Если входные изображения сырые:

1. построить master bias и master dark отдельно для режимов gain 1000 и 400;
2. построить нормированные master flat отдельно для R и H-alpha;
3. выполнить bias/dark subtraction и flat-fielding;
4. создать маску горячих, холодных, насыщенных и нелинейных пикселей;
5. не заменять плохие пиксели незаметно: маска должна дойти до centroid fit.

Нельзя объединять кадры с разными gain в одну шумовую модель. R и H-alpha также
следует редуцировать раздельно из-за PSF, DCR и различий потока.

### 3. Первичный plate solving

- Использовать существующий WCS 2025-09-03 как initial guess.
- Решить кадры 2025-09-02 и 2025-10-10 через Astrometry.net или перенос решения от
  соседнего кадра с последующим сопоставлением звезд.
- Проверить parity, масштаб, поворот и отсутствие ложных решений.
- Сохранить исходный WCS и уточненный WCS раздельно; не перезаписывать raw FITS.

### 4. Опорный каталог Gaia

- Запрашивать Gaia DR3 один раз на поле и кэшировать исходный ответ вместе с датой,
  URL/версией сервиса и параметрами запроса.
- Переносить `ra`, `dec` на эпоху каждого кадра с учетом `pmra`, `pmdec`, parallax;
  для наиболее точной стадии использовать `SkyCoord.apply_space_motion` или
  эквивалентную проверенную реализацию.
- Отбрасывать звезды без подходящего astrometric solution, дубли, переменные
  фотоцентры, насыщенные и слишком слабые источники.
- Ограничения по G подбирать по фактической S/N, а не фиксировать навсегда 5–16.5.
- Сохранять Gaia source_id каждой использованной звезды.

Основной notebook обращается к официальному Gaia Archive через `astroquery`.
Для воспроизводимости следует кэшировать исходный ответ каталога вместе с датой,
ADQL-запросом и версией сервиса.

### 5. Центрирование звезд и модель поля

Baseline — эллиптическая 2D Gaussian из `exam`. Далее сравнить:

- weighted Gaussian/Moffat fit;
- эмпирическую ePSF по нескольким десяткам звезд;
- aperture centroid только как контрольный метод.

Для каждого fit сохранять центр, ковариацию, flux, background, FWHM, ellipticity,
chi-square и флаг качества.

Вместо независимого простого линейного решения каждого кадра предпочтительна
иерархическая схема:

1. стабильная общая модель дисторсии камеры по всем хорошим кадрам;
2. на каждом кадре — только translation, rotation, scale и при необходимости shear;
3. локальная поправка в районе траектории астероида по контрольным звездам;
4. iterative robust clipping и leave-one-out проверка опорных звезд.

Существующую SIP-модель можно использовать как начальное приближение, но ее
коэффициенты и устойчивость между кадрами надо проверить по картам остаточных
векторов. Отдельно построить остатки против `x`, `y`, magnitude, color, FWHM,
времени и воздушной массы.

### 6. Поиск астероида

Первичный прогноз брать из JPL Horizons/MPC с обязательным сохранением:

- времени запроса;
- observer code/топоцентрического положения;
- идентификатора решения и параметров эфемериды;
- координат и скоростей на каждый кадр.

Поиск выполнять в расширенном окне вокруг прогноза. Если объект виден на отдельных
кадрах, связать detections ограничением на почти линейное движение. Если не виден:

1. зарегистрировать кадры по звездам;
2. перебрать сетку угловых скоростей около эфемеридной;
3. для каждой скорости выполнить shift-and-stack в системе астероида;
4. выбрать согласованный максимум по S/N и форме PSF;
5. проверить найденный трек на независимых половинах серии.

Обязательны негативные тесты: соседние скорости, случайные позиции и инверсия
порядка времени не должны давать сопоставимый устойчивый объект.

### 7. Складывание без потери астрометрической информации

Один стек всей ночи полезен для обнаружения, но не должен быть единственным
астрометрическим измерением: он уничтожает временную структуру и может сместить
фотоцентр при неверной скорости.

Предусмотреть три продукта:

- **star-aligned stack** — контроль поля, масок и неподвижных источников;
- **asteroid-aligned full stack** — подтверждение обнаружения и общая S/N;
- **неперекрывающиеся короткие подстеки** — собственно временной ряд, если один
  кадр слишком слаб.

Размер подстека выбрать injection-тестами, например начать с 5–10 кадров. Для
каждого подстека использовать эффективное взвешенное время. Перекрывающиеся
подстеки годятся для визуализации, но создают коррелированные измерения и без
полной ковариации не должны идти в финальный fit.

### 8. Центрирование астероида

Проверить несколько моделей:

- stellar PSF, если смаз за 5 секунд пренебрежим;
- PSF, свернутая с отрезком известной длины и направления;
- одновременный forced fit на всех кадрах/подстеках с общей траекторией;
- forward model непосредственно по пикселям как конечный высокоточный вариант.

Модель должна возвращать не только `(x, y)`, но и ковариацию, flux, background,
trail length/angle и goodness-of-fit. Смаз вычислять из fitted angular velocity и
экспозиции, а не оценивать только визуально.

### 9. Координаты и локальное движение серии

Пиксельные координаты астероида преобразовать в `ξ, η` той же моделью, что и
звезды. Затем выполнить совместный взвешенный robust fit обеих координат по времени.

Для каждой серии сохранить:

- `t0`, `RA0`, `Dec0`, `ξ0`, `η0`;
- `vξ`, `vη` и, если обосновано, ускорения;
- полную матрицу ковариации параметров;
- число исходных/принятых кадров;
- RMS, robust scatter, reduced chi-square;
- корреляцию и автокорреляцию остатков;
- версию модели и причины исключения точек.

Среднее отдельных координат без модели движения использовать нельзя. Значение на
центральный момент из локального fit является корректным аналогом «среднего серии».

### 10. Реалистичная оценка ошибок

Формальная ошибка centroid fit обычно слишком оптимистична. Итоговая ошибка должна
включать:

- шум изображения астероида;
- неопределенность plate model;
- ошибки Gaia после переноса на эпоху;
- остаточную дисторсию и DCR;
- временную корреляцию атмосферы/ведения;
- неопределенность скорости при shift-and-stack.

Использовать как минимум residual bootstrap блоками по времени или jackknife по
кадрам/подстекам. Проверить закон `sigma ∝ N^−1/2`; выход на plateau покажет уровень
систематик. В отчетах всегда разделять внутреннюю precision и внешнюю accuracy.

### 11. Контрольные эксперименты

Чтобы отличить небесный сигнал от систематики, прогнать тот же pipeline на:

- Gaia-звездах, временно исключенных из plate solution («звезда как астероид»);
- нескольких звездах рядом с траекторией астероида;
- неподвижных искусственных источниках, внедренных в реальные кадры;
- движущихся искусственных источниках известного блеска, движения и wobble;
- R и H-alpha независимо;
- первой/второй половине ночи и разных наборах опорных звезд.

Injection-recovery должен ответить, при какой амплитуде и периоде текущая выборка
реально дает заданную completeness и false-alarm probability. Без этого верхний
предел полезнее неподтвержденного «обнаружения».

### 12. O−C как диагностика

Для каждого измерения вычислить O−C относительно сохраненного снимка эфемериды.
O−C нужен для:

- проверки отождествления;
- выявления грубого смещения времени или WCS;
- сравнения ночей с опубликованной орбитой;
- передачи стандартных астрометрических положений.

Однако обновление эфемериды не должно менять измеренные `RA/Dec`, локальную модель
или исходные residuals. Данные эфемериды хранятся как отдельный versioned input.

### 13. Поиск периодического сигнала

К этой стадии переходить только после стабильной астрометрии и null tests.

1. Собрать residuals после общей модели движения/орбиты с полной ковариацией.
2. Построить Generalized Lomb–Scargle periodogram и spectral window.
3. Отдельно проверить опубликованный период 94.864 h, не выдавая этот targeted test
   за независимый blind search.
4. Оценить false-alarm probability Monte Carlo на тех же временах и ошибках,
   сохраняя красный шум и ночные систематики.
5. Сравнить baseline и baseline + sinusoid по cross-validation/BIC и по recovery
   внедренных сигналов.
6. Проверить стабильность периода, амплитуды и фазы при исключении каждой ночи.
7. Сопоставить астрометрический residual с flux/light curve, FWHM, фоном, цветом,
   координатой на матрице и parallactic angle.

Нельзя интерпретировать самый высокий пик как двойственность без spectral window,
Monte Carlo и воспроизводимости на независимых эпохах.

- recovery линейного движения и известного centroid shift;
- отсутствие периодического сигнала в pure-noise/null sample;
- воспроизводимость результата при фиксированном random seed.

## Что считать успешным первым результатом

Работа первого цикла завершена, когда для хотя бы одной полной серии одновременно
выполнено следующее:

1. объект автоматически найден и подтвержден split-half тестом;
2. все использованные кадры и отбраковки прослеживаются до исходных FITS;
3. положение каждой точки и серии имеет реалистичную ковариацию;
4. карты звездных остатков не показывают неучтенной зависимости от поля/времени;
5. контрольные звезды проходят тот же pipeline без ложного движения;
6. положение на центральную эпоху и его O−C воспроизводятся одним запуском;
7. есть численная оценка предела обнаружения периодического wobble.

Только после этого имеет смысл накапливать новые эпохи и обсуждать физическую
интерпретацию возможного 8-mas сигнала.
